The R4 JSON schema requires only `code` and `resourceType` on Observation and does not require `status`; it has no check that a period starts before it ends. That is why operators 9 and 14 are strict only. Without `--strict`, their cases are reported as not checked at that layer, never as valid or invalid.

## 1. `observation.duplicate_with_changed_issued`

Adds a corrected copy (new id, status corrected, later issued, new value).

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Latest becomes the copy
- Eligible targets: The latest Observation for its code (by effective time, then issued) with a numeric valueQuantity.value and an issued or effective time.
- Paths it may change: /entry/{n+1} (a new entry after the original)
- Reversible: Yes: remove the added entry.
- Arguments:
  - `days_later` (default `3`): Days between the original issued time and the correction.
  - `value_delta` (default `-1.1`): Added to the value in the corrected copy.

Before:

```text
{"id": "obs-glucose-3", "status": "final", "issued": "2026-01-10T09:12:00Z", "valueQuantity": {"value": 7.2}}
```

After:

```text
+ {"id": "obs-glucose-3-corrected", "status": "corrected", "issued": "2026-01-13T09:12:00Z", "valueQuantity": {"value": 6.1}}
```

## 2. `observation.correction_sequence`

Sends the bundle twice: first preliminary, then final with a new value.

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Latest is the final value
- Eligible targets: The latest Observation for its code with a numeric valueQuantity.value.
- Paths it may change: /entry/{n}/resource/status, /issued, /valueQuantity/value (second step)
- Reversible: Yes: ingest only the first step and restore the value.
- Arguments:
  - `hours_later` (default `6`): Hours between the two versions' issued times.
  - `value_delta` (default `-0.9`): Added to the value in the final version.

Before:

```text
{"id": "obs-glucose-3", "status": "final", "valueQuantity": {"value": 7.2}}
```

After:

```text
step 1 {"status": "preliminary", "value": 7.2}, step 2 {"status": "final", "value": 6.3}
```

## 3. `identifier.duplicate_business_identifier`

Two different resources share one identifier system and value.

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Unchanged count unless declared
- Eligible targets: A resource with an identifier that has a system and value, and another resource of the same type.
- Paths it may change: /entry/{m}/resource/identifier of the second resource
- Reversible: Yes: restore the second resource's identifier.
- Arguments: none

Before:

```text
A {"identifier": [{"system": ".../lab-accession", "value": "ACC-1"}]}, B {"identifier": [{"value": "ACC-2"}]}
```

After:

```text
B {"identifier": [{"system": ".../lab-accession", "value": "ACC-1"}]}
```

## 4. `medication.conflicting_active_requests`

Two active MedicationRequests for the same medication with different doses.

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Both kept
- Eligible targets: An active MedicationRequest with dosageInstruction[0].doseAndRate[0].doseQuantity.value.
- Paths it may change: /entry/{n+1} (a new entry after the original)
- Reversible: Yes: remove the added entry.
- Arguments:
  - `dose_factor` (default `2`): Multiplies the dose in the conflicting copy.

Before:

```text
{"id": "medrq-a1", "status": "active", "doseQuantity": {"value": 500}}
```

After:

```text
+ {"id": "medrq-a1-conflict", "status": "active", "doseQuantity": {"value": 1000}}
```

## 5. `time.backdate_effective`

Moves effective[x] N days before issued.

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Order by effective time
- Eligible targets: An Observation or DiagnosticReport with a full effectiveDateTime and issued.
- Paths it may change: /entry/{n}/resource/effectiveDateTime
- Reversible: Yes: restore effectiveDateTime.
- Arguments:
  - `days` (default `30`): Days before issued.

Before:

```text

```

After:

```text
{"effectiveDateTime": "2025-12-11T09:12:00Z", "issued": "2026-01-10T09:12:00Z"}
```

## 7. `time.date_only_precision`

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Same as base
- Eligible targets: An Observation or DiagnosticReport whose effectiveDateTime has a time part. issued is an instant and must keep its time, so it is never changed.

- Arguments: none

## 10. `quantity.equivalent_unit`

Rewrites a quantity in an equivalent UCUM unit (1 g/L as 1 mg/mL).

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Same value after conversion
- Eligible targets: An Observation valueQuantity whose UCUM code has a factor-1 equivalent: g/L, mg/mL, mmol/L, umol/mL, mg/L, ug/mL, mmol/mol, umol/mmol.

## 15. `reference.to_urn_uuid`

Rewrites a resource's fullUrl to urn:uuid: and every reference to it.

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Same as base
- Eligible targets: A resource whose fullUrl is not already a urn:uuid and that at least one reference points at.
- Paths it may change: /entry/{n}/fullUrl and every reference to it
- Reversible: Yes: restore the fullUrl and the references.
- Arguments: none

Before:

```text
{"fullUrl": "https://example.org/fhir/Patient/pat-a"} ... {"subject": {"reference": "Patient/pat-a"}}
```

After:

```text
{"fullUrl": "urn:uuid:5b0e7c1a-..."} ... {"subject": {"reference": "urn:uuid:5b0e7c1a-..."}}
```

## 16. `reference.to_absolute_url`

Rewrites references to absolute URLs on a declared base.

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Same as base
- Eligible targets: A resource that at least one relative reference (Type/id) points at.
- Paths it may change: /entry/{n}/fullUrl (set to base/Type/id) and every reference to it
- Reversible: Yes: restore the relative references.
- Arguments:
  - `base` (default `https://example.org/fhir`): Absolute base URL for the references.

Before:

```text
{"subject": {"reference": "Patient/pat-a"}}
```

After:

```text
{"subject": {"reference": "https://example.org/fhir/Patient/pat-a"}}
```

## 17. `reference.dangling_target`

Points a reference at a resource that is not in the bundle.

- Version: 1
- Intended: Invalid
- Caught by: references
- Effect on the view: Rejected or flagged
- Eligible targets: A reference that resolves inside the bundle, outside contained resources. select.field limits it to one member, such as result.
- Paths it may change: the reference string
- Reversible: Yes: restore the reference.
- Arguments: none

Before:

```text
{"result": [{"reference": "Observation/obs-glucose-3"}]}
```

After:

```text

```

## 18. `reference.cross_patient`

Points one resource's subject at another patient in the bundle.

- Version: 1
- Intended: Invalid
- Caught by: references
- Effect on the view: Rejected, never merged
- Eligible targets: A resource with a subject or patient reference that also links to another resource of the same patient (for example its encounter), in a bundle with at least two patients.
- Paths it may change: /entry/{n}/resource/subject/reference
- Reversible: Yes: restore the subject.
- Arguments: none

Before:

```text
{"subject": {"reference": "Patient/pat-c1"}, "encounter": {"reference": "Encounter/enc-c1"}}
```

After:

```text
{"subject": {"reference": "Patient/pat-c2"}, "encounter": {"reference": "Encounter/enc-c1"}}
```

## 19. `bundle.reorder_entries`

Shuffles entry order.

- Version: 1
- Intended: Valid, no change in meaning
- Caught by: none
- Effect on the view: Same as base
- Eligible targets: A bundle with at least two entries. The new order is never the original order.
- Paths it may change: /entry (move operations)
- Reversible: Yes: apply the inverse permutation.
- Arguments: none

Before:

```text
entry 0 Patient, 1 Encounter, 2 Observation
```

After:

```text
entry 0 Observation, 1 Patient, 2 Encounter
```

## 21. `resource.unexpected_type`

- Version: 1
- Intended: Valid, edge case
- Caught by: none
- Effect on the view: Ignored, no crash
- Eligible targets: A bundle with at least one Patient. resource_type is Specimen, Device or Flag.
- Paths it may change: /entry/- (a new last entry)
- Reversible: Yes: remove the added entry.
- Arguments:

```text

```
